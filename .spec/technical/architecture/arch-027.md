## Overview

Every story in every epic, checked against the backend as it actually runs today (`apps/api-ts` — NestJS/Prisma/TypeScript — and `apps/api-go` — Go), not against the spec's description of what it should do. This repo underwent ADR-027's collapse from ~18 microservices to two apps, and a lot of prior documentation — including this repo's own test-plan docs before their own ground-truth passes — describes endpoints and seams that were never carried into that collapse. Every claim below is a direct code citation, not an inference from a spec file.

**Scope**: backend only, per request. Frontend (`apps/web`, `apps/mobile`) is out of scope for this pass.

**Method**: 12 of the 13 epics were surveyed by independent parallel research passes (one per epic, each reading that epic's stories and the real code, with no access to the others' findings). EPIC-012 is carried over from the same-day [TP-013](../test-plans/tp-013.md) ground-truth-and-fix pass, which went scenario-by-scenario rather than story-by-story — see that doc for the full 59-scenario detail (31 tested, 6 real bugs found and fixed, 4 resolved, 17 architecturally N/A, 1 still open) this section's five rows summarize.

**Status values**: `implemented` — the story's core behavior genuinely works end-to-end. `partial` — some acceptance criteria are met, others are missing, unenforced, or built but not wired to any caller. `not_implemented` — little or nothing exists.

## Headline numbers

**11 implemented · 33 partial · 14 not_implemented**, out of 58 stories across 13 epics (updated by the 2026-09-16 remediation pass below — see end of doc for what moved and why).

`partial` is the dominant outcome — not because work is half-done in the usual sense, but because a small number of *systemic* gaps recur across nearly every epic. Read those first; they explain most of the 34.

## Systemic patterns

These seven patterns account for the large majority of every `partial`/`not_implemented` finding below. They're listed once here instead of repeated per story.

1. **No scheduler exists anywhere** — **infrastructure added 2026-09-16, most jobs still unbuilt.** `apps/api-ts` now has `@nestjs/schedule` (`ScheduleModule.forRoot()` in `AppModule`) and `apps/api-go` now has an in-process `internal/scheduler` package — both run inside the existing containers, no new service (ADR-027: one binary per runtime). Two real jobs are wired: `CompetencyExpiryService` (hourly, TS) and the delegation expiry sweep (`DELEGATION_EXPIRY_INTERVAL`, default 24h, Go). The other four — DP-040 (assignment generation, EPIC-009), DP-048 (participation scoring, EPIC-009), DP-050 (rotation sweep, EPIC-012), DP-051 (budget aggregation, EPIC-006), DP-053 (outcome-evaluation trigger, EPIC-008) — still have no underlying logic to schedule, not just no timer; adding the scheduler didn't reduce those to one-line fixes.
2. **Built, tested, and never called** — the highest-value class of finding here, because the fix is wiring, not new logic. **The constitutional-reviewer instance is fixed (2026-09-16)**: `ProposalModule` now binds `CONSTITUTIONAL_REVIEWER` to a real `HttpConstitutionalReviewer` calling `audit-service`'s live `POST /audit/reviews` — every proposal is no longer permanently blocked (see US-045; a real, separate content-detection gap remains). The other three in this pattern are still open: `delegation`'s resolved `DelegatorsFor` result is discarded in `CastBallot` (`_, _ = ...`) — investigated this session (see US-043), and it turns out to need a real design decision about vote-weighting/proxy-ballot mechanics, not a mechanical wire-up. `jurisdiction.isEligible` is correct and unit-tested but has zero non-test callers anywhere — voting trusts a caller-supplied citizen list instead. `IamService.evaluate` has zero real call sites outside its own test suite.
3. **No citizen-facing write path for the thing the story is about.** `governance_role` assignment (who becomes an auditor/reviewer/operator/review_body) is DB-seed only — no endpoint exists to grant one, which quietly blocks scope-challenge resolution (EPIC-002) and scope assignment (EPIC-002) in practice, since both require a `review_body` holder nothing can create. `residency.verified` is never set `true` by any code path. No code path ever creates a `project` row from an approved proposal, and `project.status` can never change after creation.
4. **No read-back for data citizens submit** — **the competency and proposal instances fixed 2026-09-16.** Competency conflict-of-interest declarations (`GET /competency/conflicts`) and challenges (`GET /competency/competency-challenges`), and proposal constraints (`GET /proposal/proposals/:id/constraints`) and budget info (`GET /proposal/proposals/:id/budget`), are all readable now — each was a missing service method + controller route sitting on top of an RLS policy that already allowed public `SELECT`, confirmed by grep before writing any of them. Not yet touched: a problem's aggregate support count/supporter list has no route at all (US-011).
5. **Identity/authorization is largely unauthenticated as deployed.** The `x-citizen-id` header (TS side) is explicitly code-commented as an "interim seam," self-declared with no verification behind it. `apps/api-go`'s delegation endpoints bind `delegator_id` straight from the request body with no identity check. `apps/api-go`'s `/auth/revoke-all` and `/auth/purge` have zero auth middleware despite a comment claiming mesh mTLS protects them — no service mesh, SPIFFE, or mTLS exists anywhere in the repo.
6. **Unit-tested but never proven over real HTTP.** A large share of `partial`/`implemented` stories have solid, often Postgres-backed, service-level unit tests but zero e2e coverage of the actual controller route: proposal's `advance()` gate, all four deadlock routes, voting's tally/certify endpoints, and — worst of all — delegation's *entire* HTTP surface.
7. **`apps/api-go`'s CI job never ran its own Postgres-backed tests** — **fixed 2026-09-16.** `.github/workflows/ci.yml`'s `go` job now has its own Postgres service, `TEST_DATABASE_URL`, and `REQUIRE_DB_TESTS` (mirroring the `ts` job's own BUG-004/TI-02 fix, applied the same way to all four `pgtest_test.go` helpers). Verified locally against a real Postgres before landing: every previously-skipped test passed on the first run, including `TestPGDelegationLifecycle`, `TestPGAuthLoginRefreshStepUp`, `TestPGVotingCastFlow`/`TallyCertify`, and `TestPGAuditReviewAndGate` — these were correct all along, just never actually run.

Three epics sit apart from these patterns: **EPIC-013** (Platform Reliability & Security Ops) is 6-of-7 `not_implemented` because it's genuinely unbuilt infrastructure (multi-region, mTLS, SLOs, break-glass) with no corresponding code yet, not a wiring gap. **US-023** (AI synthesis, EPIC-005) is a deliberate, documented scope carve-out (ADR-031), not a gap. **EPIC-012** already got its own full remediation pass this session — see TP-013.

## EPIC-001 — Citizen Identity System (3 implemented · 2 partial)

- **US-001** *Register and obtain a single verified civic identity* — **implemented.** Unit: `identity.service.spec.ts` (duplicate-hash rejection, hash-not-raw storage, activation on verified outcome, RLS). E2E: `identity.controller.e2e.spec.ts` (real HTTP+Postgres, register→verify→activate→read-own, duplicate `legalIdentifier` 409, 401/403, `/status`). Gap: every request's citizen identity rests on the unverified `x-citizen-id` header (pattern #5) — solid otherwise.
- **US-002** *Cast a secret ballot and later confirm it was counted* — **partial.** Unit: `voting/service_test.go` (cast/verify/tally/certify/issue-tokens, all via direct Service calls). E2E: **none** — the one router-level test only hits `/healthz`/`/readyz`. Gap: `EligibilityToken` is a plain bearer token, not a blind signature, and `EncryptedChoice` is stored/tallied as a literal client-supplied string — `Tally()`'s own comment admits real threshold decryption is unimplemented. Handlers also have zero authorization checks (pattern #5).
- **US-003** *Independent auditor: review identity-creation events* — **partial.** Unit: `duplicate-detection.service.spec.ts`, `audit/service_test.go`. E2E: `identity.controller.e2e.spec.ts` (HP-6), `audit/router_test.go`'s hash-chain suite. Gap: `identity.service.ts`'s `register()` — the actual identity-*creation* event — never calls `audit.emit`; only activation/revocation/duplicate-flagging do. `ACTION_TYPE_BY_VERB` has no `identity.citizen_registered` entry.
- **US-004** *Identity registrar: revoke identities under qualifying conditions* — **implemented.** Unit: `identity-revocation.service.spec.ts` (full request/execute state machine). E2E: `identity-revocation.controller.e2e.spec.ts` (403/404/422 fail-closed/full 2-of-2 flow). Gap: the session-revoker cascade to `auth-service` is fire-and-forget and only mock-tested, never against a real running `auth-service`.
- **US-005** *Oversight board: require multiple approvals before disabling participation* — **implemented.** Unit + E2E: same suites as US-004 plus `governance-role.service.spec.ts`'s layer-check/self-approval/2-of-2 logic. Gap: `listApprovals` (public read, satisfies "all approvers are recorded") has no e2e test asserting it returns both approvers for a completed revocation.

## EPIC-010 — Delegated Expertise / Liquid Democracy (0 implemented · 2 partial)

- **US-043** *Delegate my vote in a domain to a trusted specialist* — **partial.** Unit: `service_test.go` covers validation, competency-gating, cycle rejection, chain resolution — all pass. E2E: the Postgres-backed lifecycle test now genuinely runs in CI (pattern #7 fixed 2026-09-16 — confirmed by running it directly against real Postgres this session, all green); no test calls the real HTTP handlers at all (pattern #6, unchanged). Gap: `create` still trusts `delegator_id` from the JSON body with zero identity binding (pattern #5). **Investigated the deeper gap this session, not fixed**: `voting`'s `CastBallot` discards the resolved delegator list (`_, _ = ...`). Casting synthetic ballots for each delegator, adding a weight field, or something else are all live options; this needs a decision before code, not more code.
- **US-044** *Revoke delegation; auto-expire* — **partial** (scheduler half fixed 2026-09-16). The formal DP-045 sweep is now real: `apps/api-go/internal/scheduler` (new package, in-process, no separate container per ADR-027) calls `delegationSvc.ExpireDue` on a `DELEGATION_EXPIRY_INTERVAL` timer (default 24h) from `main.go`. E2E tier now runs in CI too (pattern #7). Gap: the ownership check on revoke is still skipped entirely when the (never-populated) identity header is empty — as actually deployed, any caller can still revoke any citizen's delegation; that's an identity-binding gap (pattern #5), not a scheduling one, and is unchanged.

## EPIC-011 — Constitutional Layer (0 implemented · 1 partial · 1 not_implemented)

- **US-045** *Block proposals that violate protected rights* — **partial** (wiring fixed 2026-09-16, a real gap remains). `ProposalModule` now binds `CONSTITUTIONAL_REVIEWER` to `HttpConstitutionalReviewer`, which genuinely calls `audit-service`'s `POST /audit/reviews` (new `constitutional-reviewer.port.spec.ts`, real local-HTTP-server test, 7 cases) — proposals are no longer permanently stuck; a live review is recorded for every `development→voting` transition. **The remaining gap is real and unchanged, not newly discovered**: this app has no code anywhere that derives which constitutional rights a proposal's content touches, so `affected_right_ids` is always sent empty — the review now runs for real but can never actually block anything substantive (TP-013 EC-47's finding stands). - **US-046** *Elevated thresholds for constitutional change* — **not_implemented.** `threshold_rule`/`min_participation` are free-form caller-supplied parameters on any session for any proposal — nothing ties a `constitutional`-scope jurisdiction or a rights-affecting proposal to a mandatory elevated threshold. `VoteSession` has no field recording constitutional-review clearance despite a code comment claiming one exists.

## EPIC-012 — System Integrity & Anti-Capture (0 implemented · 3 partial · 2 not_implemented)

- **US-047** *Inspect the immutable public action log* — **partial.** The hash chain, verification, idempotency, and concurrency are all real and now HTTP-level tested (TP-013 HP-1/HP-7/EC-1..5/34..40/48).
