## Columns

| Column | Type | Description |
|--------|------|-------------|
| id | uuid | Primary key |
| policy_id | uuid | Attached policy |
| principal_ref | text | `citizen:<uuid>` (an individual operator/platform-operator) or `role:operator` / `role:platform_operator` (every current active holder of that role_type) |
| status | enum | pending_approval \| active \| revoked |
| proposed_by | uuid | citizen_id who proposed this attachment (cross-service ref to identity-service citizen, not FK-enforced, ADR-015) |
| created_at | timestamptz | Proposal time |

## Notes

Implements ADR-025/ARCH-024. Publicly readable. `role:*`-shaped `principal_ref` values are resolved against governance-role-service's current role holders at evaluation time (ARCH-024 §1), not stored as a fixed citizen list — a role-wide grant automatically follows role rotation (ADR-009) without re-attaching. Activates only via dual-control endorsement (TBL-042).
