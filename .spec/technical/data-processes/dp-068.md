## Description

Fast-track, time-boxed emergency elevation of a named platform-operator's (AUTH-011) access during a declared incident. Distinct from standing platform-operator appointment (DP-063), which follows the full multi-approval protocol and 14-day delayed-execution window before any access is granted. A break-glass grant is temporary incident response, not a permanent role change, so per ADR-017 the approval path is reduced but still non-unilateral (ADR-001): dual control by a second, independent, on-call platform-operator, approving in real time, substitutes for the full `citizen_supermajority` / `audit_confirmation` / `body_endorsement` set required for DP-063.

### Grant flow

1. An on-call platform-operator (TBL-032, role_type=platform_operator) declares a SEV2+ incident and requests break-glass elevation, citing the incident reference as `action_ref`.
2. A second, independent, on-call platform-operator co-approves in real time — recorded as an `approval` row (TBL-033) linked to the incident `action_ref`. No citizen vote, audit confirmation, body endorsement, or delayed-execution window is required.
3. On dual-control approval, governance-role-service (SRV-011) issues a time-boxed `governance_role` row (TBL-032, role_type=platform_operator, layer=implementation) scoped to the incident, with `term_start=now()` and `term_end` capped at `term_start` + 4 hours.
4. Elevated cluster and secrets access is granted for the term of the row.
5. Grant issuance automatically enqueues a mandatory post-incident audit_finding review — same review mechanism as DP-022 — to the active audit pool (AUTH-003), due within 48 hours of grant issuance.
6. Every action taken under the grant, and the grant itself, is emitted to audit.append (DP-036) tagged with the incident reference, so all break-glass activity traces to the incident that justified it.

### Expiry and revocation

The grant auto-expires at `term_end` even if never manually revoked; elevated access is withdrawn at expiry with no separate action required. Either co-approving platform-operator, or an audit body finding, may revoke the grant manually before `term_end`. Both auto-expiry and manual revocation are emitted to audit.append (DP-036) tagged with the incident reference.
