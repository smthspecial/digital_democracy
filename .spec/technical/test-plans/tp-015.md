## Scope

Chromium executes `navigator.credentials.create` and `navigator.credentials.get`
with a CDP virtual CTAP2 authenticator. The real auth router validates browser
responses against both memory and migrated Postgres stores. A same-origin test
gateway and active-identity fixture exist only in `_test.go`; they do not add
production routes or bypasses. Provisioning still uses the signed service seam.

## Checks

- Enrollment grants cannot validate as sessions and cannot be replayed.
- First credential enrollment does not issue a session; registration replay fails.
- User-verified browser assertions issue a T3 session for the expected citizen.
- Reusing a completed assertion ceremony fails.
- Refresh tokens are absent from JSON and `document.cookie`.
- Browser cookie metadata is Secure, HttpOnly, SameSite=Strict, path=/auth.
- Browser-cookie refresh rotates access tokens and invalidates the previous token.
- Logout clears the browser cookie and invalidates access and refresh.

## Execution

Install workspace dependencies and Chromium with `pnpm exec playwright install
chromium`, then run `pnpm test:passkeys`. Set `TEST_DATABASE_URL` for the disposable
Postgres tier; `REQUIRE_DB_TESTS=1` makes a missing database fail rather than skip.
`PASSKEY_CHROMIUM_PATH` can select an existing local Chromium executable. CI runs
both stores with mandatory database configuration and the pinned browser package.

## Remaining checks

The virtual authenticator verifies browser/protocol interoperability, not real
platform PIN/biometric UI or hardware. Manually register and log in using a
physical/platform passkey on the actual HTTPS origin before pilot release.
Real identity proofing and grant delivery remain TASK-002 integration work;
this harness does not claim to exercise them or the citizen-facing UI.
