## Context

ARCH-009 (2026-08-27) defined unit/integration/e2e for an 18-microservice topology. ADR-027 collapsed that into two runtime apps before ARCH-009's scenarios were implemented. Most former cross-service seams are now in-process calls inside one NestJS app; the only real remaining cross-process boundary is `apps/api-ts` ↔ `apps/api-go` (plus NATS). Separately, the 2026-09-14 audit found every `apps/api-ts` `*.service.spec.ts`/`*.controller.e2e.spec.ts` file connects to real Postgres — none is a mocked-dependency unit test despite the naming.

`apps/web` remains a bare Next.js scaffold with no feature UI to drive a browser through.

## Decision

Three tiers, redefined for the current architecture:

- **Unit**: in-process, one module, no database, no network — dependencies mocked/faked. Exists today only in `apps/api-go`'s `voting` package (`service_test.go` with `NewService(nil,nil,nil)`). `apps/api-ts` has none; TI-07/TI-08 build this tier by extracting pure decision logic out of Prisma-coupled services.
- **Journey** (renamed from "integration"; "integration" is retired as ambiguous between single-service-real-DB and cross-service): a real Postgres-backed pass through one app's controller→service→DB stack (what `*.controller.e2e.spec.ts` already does), OR a real cross-process HTTP call between `apps/api-go` and `apps/api-ts`. Both count as this tier; a scenario doc states which.
- **E2E**: reserved for a browser-driven client hitting the full stack. Does not exist and cannot exist until `apps/web` has feature UI (out of scope until that epic is planned).

Rename convention going forward: existing `*.service.spec.ts`/`*.controller.e2e.spec.ts` files keep their names (TI-06 renames them file-by-file as each is touched, not in one sweep) but this ADR is the authority on what tier they actually are — Journey (single-app, real DB), not unit or e2e.

`testing/e2e-suite` (TI-09) hosts cross-process Journey tests spanning both apps; fixtures built only through each app's own public API (ARCH-009 §2's convention carries forward unchanged).

## Consequences

- ARCH-009 and ARCH-010..014 are marked historical per ADR-033, not deleted — their HP-N/EC-N scenario catalog is still useful, their topology assumptions are not.
- A "journey" test asserting only within one app does not prove the cross-app seam works; `testing/e2e-suite` is the only place that claim can be made truthfully.
- Coverage gates (TI-14/TI-15) key off this taxonomy, not ARCH-009's.
