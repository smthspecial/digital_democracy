## Context

`JurisdictionService.isAffected` implements member-OR-verified-resident; the epic's AC2/DP-025 read as residency-AND-membership. No minimum residency period, impact-dimension-to-scope mapping, scope-assignment authority, or jurisdiction-boundary mutation control exists. `development → voting` is blocked pending constitutional review (SRV-012), which doesn't exist (ADR-030).

## Decision

- **Eligibility (D7)**: split the predicate. `isAffected` (member OR verified resident) stays as-is — it answers AUTH-010's `jurisdiction:affected` standing-to-challenge question. A new `isEligible` implements strict AND (residency AND membership), satisfying AC2/DP-025 for participation eligibility.
- **Minimum residency (D8)**: `Jurisdiction.minResidencyDays`, seeded 180 at municipality-and-above, 0 at property/street (FR-012's 6–12 month band).
- **Impact-dimension mapping (D9)**: one exported `DIMENSION_LEVEL_FLOORS` constant (geographic/economic/environmental/infrastructure/legal → recommended floor level), provisional, enforced — assignment below the floor requires a documented reason.
- **Scope assignment authority (D10)**: gated on an active `review_body` role via `GOVERNANCE_ROLE_CHECKER`; new `proposal:scope:assign` AUTH-010 row (`role.term + coi.none`, T3).
- **development → voting (D11, supersedes ADR-030's blanket block)**: ships now behind a fail-closed `ConstitutionalReviewer` seam, default not-cleared — the same seam pattern as `CompetencyChecker`/`AuditEmitter`. Not a silent default-clear.
- **Jurisdiction boundaries (D12)**: boundary data stays externally authored; the platform stores a pointer + hierarchy placement. Add an immutability trigger — `jurisdiction_worker_update` is currently an unrestricted `FOR UPDATE` policy to `api_worker`.
- **Cross-app eligibility auth (D13)**: `apps/api-go` authenticates to `apps/api-ts`'s eligibility check the same interim way ADR-030 already established for citizen context (a shared env-var secret) — single point to replace when mTLS lands.

## Consequences

E2-01 (schema) through E2-13 (cross-process e2e) build against this. `eligibility-requires-both-residency-and-membership`'s current failing state (audit finding) is closed by `isEligible`, not by changing `isAffected`.
