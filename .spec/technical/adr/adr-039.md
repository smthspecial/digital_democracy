## Context

The audit's BUG-001/BUG-003 fixes already shipped code decisions this repo's spec-first convention expects recorded: which side owns the audit write contract, how the action-type vocabulary is bridged, and whether a misconfigured seam fails loudly.

## Decision

- **Contract ownership (D43)**: `apps/api-ts` conforms to `apps/api-go`'s existing `POST /audit/log` contract (snake_case, string payload) — that route is already correct and tested; the pre-pivot emitter used the same shape. `apps/api-ts` does not gain a second route.
- **Action-type vocabulary (D44)**: the 7-value `TBL-034` enum stays fixed; `apps/api-ts`'s sixteen dotted verbs map onto it via one table (`ACTION_TYPE_BY_VERB` in `audit-emitter.ts`), with the original verb preserved inside the payload. Revisit only if auditors report the coarse classification is insufficient.
- **Delivery guarantee (D42, partially resolved)**: stays best-effort/non-blocking (FR-005's audited action must never fail because logging failed) — but a failed delivery is now `logger.error`, not a swallowed warn. A durable outbox (CC-02) remains open, deferred: best-effort-but-loud is the interim state, not the end state.
- **Notification carve-out (D46)**: notification-service stays a declared no-op (`NoopNotificationEmitter`-shaped default) until its owning epic is planned — not a live-looking URL that 404s. Both runtimes warn at startup if the env var is set anyway.

## Consequences

Recorded after the fact because the fix shipped as a bug fix, not a design proposal — the decision still needed a durable record per this repo's convention.
