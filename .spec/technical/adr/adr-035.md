## Context

No `advance()`/transition method exists on `ProposalService`; `proposal.controller.e2e.spec.ts` moves status via raw SQL. `supportThreshold` is a client-supplied integer with no population backing (DTO comment admits it). No trigger moves a proposal `draft → gathering_support`. `development → voting` is blocked pending SRV-012 (ADR-030).

## Decision

- **Threshold formula (D14)**: store `supportRateBps` + `minThreshold` + `maxThreshold` per jurisdiction; per-scope-level defaults reproduce FR-017's published examples at its reference populations.
- **Zero/unknown population (D15)**: clamp to `minThreshold`; refuse (422) when population is null. Never silently default to 0/1.
- **Who moves the lifecycle (D16)**: one shared domain function, callable by neither side unilaterally in isolation — a proposer decides when a draft goes public and when a developed proposal is ready for ballot; crossing the support threshold is system-triggered, not proposer-declared.
- **What counts as support (D17)**: endorsing the proposal itself (not the linked problem) gates the threshold — restores the pre-pivot (tp-004) semantics; this is the only reading under which the gate discriminates between competing proposals.
- **Evidence at submission (D18)**: at least one evidence row required; `kind: "statement"` permitted (a citizen's own account satisfies FR-015 without requiring a document).
- **Comment moderation (D19)**: open to any citizen for now; absence of a takedown path is a recorded, accepted gap, not an oversight.
- **development → voting while SRV-012 doesn't exist (D20)**: fail-closed, injectable `ConstitutionalReviewer` (same seam as ADR-038's D11) — default deny; the transition records which reviewer answered. Never a silent default-clear.
- **issue_type (D21)**: a filterable label, one pipeline — not yet a behavior fork.
- **Candidate impact scope (D22)**: derived from the submitter's verified residency when no jurisdiction is given; explicit override accepted; marked provisional via `scope_confirmed_at` until a review body confirms it.

## Consequences

E3-01 (schema) through E3-16 (e2e) build against this; `proposal-advance-gated-by-threshold` and the six capabilities gated behind it (audit findings) close via `ProposalService.advance()` (E3-09), not by patching the raw-SQL test helper.
