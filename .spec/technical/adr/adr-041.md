## Context

The static assessment and disposable local penetration tests confirmed the
findings recorded in BUG-005 through BUG-013. The user requested tickets and
remediation for every finding. SEC-10's replay limitation is tracked as BUG-014.
Requirements remain unchanged; these controls enforce existing authorization,
privacy, eligibility, delayed execution and workload identity requirements.

## Decision

- Go internal mutations require authenticated service requests; citizen ballot
  and delegation mutations validate the real session and enforce T3/T2 and
  ownership. TS mutations require T2; governance, IAM, identity revocation and
  residency/scope review require T3.
- Sign the exact sequence `service`, `method`, `path including query`, Unix
  timestamp, random 16-byte nonce in hex, and SHA256 of the body, separated by
  newlines. Require the nonce. Consume signatures once, retaining them until the
  timestamp window expires. Persistent instances use a unique Postgres row, so
  replay protection survives restarts and spans replicas. Update both runtimes
  and the trusted identity verifier together; the old signing format is rejected.
- The pilot HMAC key is shared by trusted runtime processes. Production workload
  mTLS binds the claimed producer header to a service-account principal; the
  gateway cannot invoke internal writes. The shared key alone does not isolate a
  compromised trusted runtime. The two-app mesh policies and broker/database
  access boundaries are required in production.
- Resolve eligibility from proposal jurisdiction, active citizenship, membership,
  verified residency and its required duration. Use bounded keyset roster pages.
  Caller-supplied citizen lists are rejected.
- A configured independent cryptographic ballot proof service must validate
  ciphertext/proof for the stated election. Without it, casting fails closed.
  The current counting implementation accepts only frozen option identifiers;
  unsupported ciphertext cannot be certified. Full threshold decryption remains
  a prerequisite for encrypted production elections, not a security bypass.
- Freeze options once voting opens and check the deadline inside the atomic
  ballot write. Persist an independent random ballot reference instead of the
  eligibility token. Never emit per-ballot audit events.
- Audit entries use a stable Ed25519 signing seed; publish its public key.
  Namespace event provenance by the authenticated producer and authenticate NATS
  envelopes. Legacy placeholder signatures do not become valid automatically.
- Protocol gates require all three approval types from current, active,
  independent role holders, resolved from the governance database at release.
  Registration sets public visibility and a conservative 24-hour minimum delay
  on the server. Caller-recorded approvals and caller-selected gate policy are
  rejected; malformed legacy gates remain blocked.
- Separate migration jobs from restricted runtime credentials. Compose provisions
  per-app logins, NOLOGIN policy roles, and database CONNECT isolation. Production
  also requires TLS, the supplied workload policies and explicit dependency peers.
- Limit requests, fields and synchronous public work. Large duplicate scans,
  constitution reviews and chain verifications fail closed and require offline
  processing rather than running unbounded work on an HTTP request.
