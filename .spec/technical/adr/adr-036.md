## Context

Argument locking (FR-033), AI synthesis (US-023), and the eight-stage deadlock framework (FR-034) have zero code. `TBL-017` has no `locked` column; `TBL-008` has no objectives/measurable-outcomes/timeline; `AUTH-010` defines no `argument:lock` or synthesis permission. The pre-pivot AI-synthesis service was a fully separate store; ADR-027/028 collapsed to one database per app.

## Decision

- **Lock authority (D34)**: `civic_assignment.type=proposal_review` + `target_ref` (real existing data, `schema.prisma:598-628`) — per-proposal scoping without a new model. Matches TP-006 §1's "proposal-scoped assignment concept," which the pre-pivot code lacked.
- **AI output store (D31)**: lives inside `apps/api-ts`'s single database (Option A) — makes `ai-no-governance-write-authority` a database-enforced, testable fact (an `INSERT INTO proposal AS api_advisory` must get permission-denied), the only honest way to test a negative capability, without reintroducing the pivot-collapsed separate-runtime design.
- **Real LLM vs deterministic engine (D32)**: ship the deterministic engine now; the LLM call is a swappable port (near-zero cost to add later), explicit follow-up once a data-handling position exists. Provenance columns accommodate a real model's identifiers from day one.
- **AI safety envelope (non-negotiable, from FR-033/US-023)**: mandatory advisory label, model/engine provenance on every output, human-review flag, system-wide kill switch — these are constraints on ever shipping the engine, recorded now regardless of D32's sequencing (D45: the carve-out is scope-defensible, the safety capabilities are not deferrable with it).
- **Non-binary voting method (D33)**: ship approval voting now (Option C) — satisfies FR-032's "at least one non-binary method" with no ballot-format or secrecy change, and every existing test already assumes it. Real ranked-choice/preference-score aggregation rounds are Option A, next.
- **Deadlock reviewer assignment (D35)**: same `civic_assignment` mechanism as D34's lock authority — one authority helper for both features.
- **Objectives/outcomes timing (D36)**: required before a proposal can reach voting/approval, not at creation — preserves DP-005's low-barrier-to-draft contract; enforced as a testable pure predicate (`hasOutcomeCommitments`), not a required-at-insert column.

## Consequences

E5-01 (schema) through E5-18 (e2e) build against this. E5-09/E5-10 (synthesis computation, governance controls) stay deferred per D32/D45; the four safety capabilities do not.
