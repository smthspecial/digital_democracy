## Context

ADR-015 gave every service its own Postgres database (17 clusters in ARCH-006 §5), and ARCH-023 built the full RLS pattern on top of that assumption (per-service `<svc>_app`/`<svc>_worker` roles, per-service migrations). With ADR-027 collapsing deployment to one app per runtime, database-per-service would leave each app fanning out to many databases for tables it alone owns — all of the isolation ceremony with none of the independent-deployment benefit that justified it.

## Decision

One database per application: `api_go` holds all four Go services' tables (TBL-019…023, TBL-034…039 plus the DP-043 `protocol_change` gate state), migrated as a single set (`apps/api-go/db/migrations/0001_init`, applied automatically at boot). `api_ts` is provisioned for the TypeScript services' future tables. Consequences applied through the merge:

- Roles collapse to `api_app` / `api_worker` with the same shape ARCH-023 §2 specifies (LOGIN, no superuser, no bypass, no DELETE anywhere).
- RLS predicates are unchanged from the ARCH-023 §6 classification — only role names changed.
- References *within* the app's tables become real foreign keys (vote_option, eligibility_token, ballot → vote_session; constitutional_review → constitutional_right). References to other apps' tables (citizen_id, proposal_id, domain_id, jurisdiction_id) stay documented comments, never FKs — the ADR-015 boundary survives at the app level (ARCH-023 §5).
- The audit hash-chain trigger (§4.4) is unchanged in rule: `prev_hash` equals the previous row's `payload_hash`, or `GENESIS`.

## Consequences

- A database-level failure or a compromised connection affects all four Go services at once instead of one. Accepted for the current stage for the same reason as ADR-027: the isolation bought nothing while every consumer deploys together anyway.
- Reversible without re-cutting tables: splitting later means one schema per service plus the same predicates under restored per-service role names — the classification table already reads that way.
- `infra/compose/postgres-init.sql` creates exactly the two app databases.
