## Goal

Complete the remaining ballot cryptography, live TLS/workload isolation,
dependency maintenance and controlled release work identified after TP-016.
Deliver a reviewable production release bundle with evidence for each security
claim. Current BUG-005 through BUG-014 closures represent completed defensive
remediation; they do not prove encrypted election functionality or live-cluster
readiness. The new tasks start at `todo`.

Requirements stay unchanged. Reuse the existing two-runtime architecture,
self-hosted k3s baseline, Helm/ArgoCD, Postgres and NATS. Use the smallest reviewed
cryptographic integration that satisfies the specified election methods,
secrecy, receipt-freeness and verifiability. No protocol, trustee threshold,
cluster/domain, new paid service or production date is assumed selected.

## Exit criteria

- [ ] A real eligible citizen obtains an unlinkable one-time credential, casts an encrypted/proven ballot, verifies inclusion, and receives a durable acknowledgement through the actual clients/runtime.
- [ ] Required voting methods produce correct verified tallies; independent trustees provide valid shares, and independent public tooling reproduces results without exposing individual choices.
- [ ] Independent review verifies the secrecy, receipt-freeness, coercion assumptions and end-to-end verifiability required by ADR-002/NFR-001/NFR-003. An unmet requirement remains a release blocker; requirements are not weakened to fit a library.
- [ ] Live ingress/workload/network/database/broker tests prove intended access and deny plaintext, unauthorized workloads, producer substitution, bad certificates and cross-database access. Renewal/rotation tests pass.
- [ ] Dependency/image scans are retained for exact release digests. Remaining mitigated advisories have an exact scope, reproducible patch/exploit evidence, owner and next review date. Unexpected or unmitigated critical/high findings block release.
- [ ] Separate migration Jobs, privileged-credential disposal, coordinated signing-format cutover, data restore/forward-fix and application rollback are rehearsed. Stable audit history/key continuity and replay state are preserved.
- [ ] Replica-safe edge limits and bounded/offline work protect legitimate voting. Load/recovery/alert evidence meets the intended deployment scope and existing applicable requirements.
- [ ] Static review, full application/crypto tests, physical/browser passkey validation and staging penetration retests pass; findings and evidence are tied to exact image/schema/config versions.
- [ ] REL-001's existing business-lifecycle gates and any remaining target-scope blockers are resolved before promotion. This security plan does not silently certify unfinished governance features.
- [ ] Production target, operational readiness and deployment authorization are established at execution time; the production run has verification checkpoints and a tested abort/recovery path.

## Capacity scope

This plan includes the security-related rate/job/replica work needed to avoid
using pilot caps as a national-scale solution. NFR-009 and US-052 remain the
national load criteria; US-053/US-058 remain regional recovery/drill criteria.
TASK-006 records scope, and TASK-019 publishes measured results and unmet gates.
A self-hosted single-node staging environment cannot satisfy a regional outage
claim. If the intended release is national, those existing infrastructure
requirements must be delivered and proven before promotion; otherwise the
release evidence must clearly identify the limited environment it qualifies.
