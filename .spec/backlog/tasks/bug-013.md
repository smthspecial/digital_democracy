## Finding

Severity: **High**. Assessment: **SEC-09**.

Static deployment examples publish development ports on all interfaces, run NATS without auth/ACL configuration, use a Go Postgres bootstrap superuser, allow ingress from every namespace and reference absent mesh authorization policies. Gateway example is HTTP-only. No deployed cluster was tested.

## Evidence

See [security report](../../../testing/security/REPORT.md) and its sanitized
memory/Postgres result files. Source locations, fixtures and scope limits are
recorded there. Run [TP-016](../../technical/test-plans/tp-016.md) for reproduction.

## Required correction

Bind development infrastructure to loopback, separate migration/admin credentials from restricted runtime roles, and configure workload identity, NATS permissions and TLS for the actual two-app topology. Domain authorization remains required.

## Verification

Compose ports bind loopback, NATS authenticates and restricts subjects, migrations use separate credentials, and fresh bootstrap uses per-app restricted logins with CONNECT isolation. HTTPS Gateway, explicit NetworkPolicy peers and workload-principal/producer binding cover the two runtimes. Images exclude local secrets and run non-root. Live mesh/certificate provisioning and existing-volume credential migration remain operational prerequisites.

See [remediation](../../../testing/security/REMEDIATION.md) and
[final verification](../../../testing/security/remediation-validation.json) for
regression results, positive controls and deployment limits.
