## Finding

The new production URL guard read the first sslmode parameter while the packaged
node-postgres parser used the last. A local, network-free image check confirmed
`sslmode=verify-full&sslmode=disable` passed the guard and disabled driver SSL.
This is a configuration-validation defect, not an unauthenticated public endpoint
attack. The disposable database itself rejects plaintext independently.

## Remediation and verification

- [x] Reject duplicate sslmode in the TypeScript runtime guard.
- [x] Reject duplicate sslmode/sslaccept/sslcert in the Prisma migration guard.
- [x] Reject duplicate or case-ambiguous sslmode in Go's canonicalizing driver path.
- [x] Retest production guards, exact artifacts and real migration failures;
  valid verified connections continue to work.

Network-free before-fix reproduction observed guardAccepted=true and
driverSSLDisabled=true. Corrected runtime guard regression passes; both real
migration images reject duplicate TLS mode parameters. See
[implementation evidence](../../../testing/production-readiness/README.md).
