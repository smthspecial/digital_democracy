## Finding

Every Postgres cast held an exclusive lock on its vote session, serializing all
citizens in the same election. A cast from an independent pool timed out while
another transaction held a shared session lock.

## Fix and verification

Use a shared session row lock while retaining the exclusive credential lock
and the atomic ballot-insert/credential-spend transaction. Independent tokens
can proceed together; closing the election still waits for in-flight writes.

`TestPGVotingIndependentBallotsShareSessionLock` now accepts the independent
ballot, proves close cannot bypass an in-flight lock, then closes successfully
and rejects further casts. Sixteen concurrent issuance and spending attempts
across independent pools issue one raw credential and accept one ballot.
A reconstructed service verifies the durable receipt and rejects a spent token.
Failure controls prove rollback after the final spend write fails and safe retry
after an unavailable pool is replaced. See the
[audit checkpoint](../../../testing/production-readiness/audit-next-items-results.json).

These are bounded synthetic service/store tests, not separate deployed API
processes, national load measurements, database failover or reviewed anonymous
credentials. TASK-019's remaining production criteria stay open.
