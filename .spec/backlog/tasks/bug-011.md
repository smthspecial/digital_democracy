## Finding

Severity: **Medium**. Assessment: **SEC-07**.

A bounded 1 MiB option description was accepted and stored by both Go backends. JSON decoders lack payload limits and internal HMAC verification reads the full body before validating its signature. Entry points have no rate limiter and some read/verify operations are unbounded. No flood test was run.

## Evidence

See [security report](../../../testing/security/REPORT.md) and its sanitized
memory/Postgres result files. Source locations, fixtures and scope limits are
recorded there. Run [TP-016](../../technical/test-plans/tp-016.md) for reproduction.

## Required correction

Use per-route body, field and batch limits; cap pagination and expensive work; configure authentication/registration abuse controls. Preserve existing server timeouts.

## Verification

HTTP bodies, fields, pages and synchronous jobs are bounded. Socket-peer rate limits ignore spoofed forwarded headers. Public Go reads are capped; oversized verification/review/duplicate jobs fail closed. Production distributed per-citizen rate limiting remains an operational prerequisite.

See [remediation](../../../testing/security/REMEDIATION.md) and
[final verification](../../../testing/security/remediation-validation.json) for
regression results, positive controls and deployment limits.
