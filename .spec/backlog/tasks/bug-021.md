## Finding

The local tally guard lived in one Service's mutex/map. Another Service or a
restart recomputed and overwrote the public tally, including its computation
timestamp. A real Postgres regression and the memory-store regression both
failed before the fix.

## Fix and verification

Read the persisted result before computing. The memory store and Postgres now
retain the first committed tally; competing writers return that result.
Postgres uses a single atomic `COALESCE` update. Remove the redundant process
mutex and per-election cache. No schema migration is required.

`TestTallySurvivesServiceRestart` and `TestPGVotingReplicaTally` exercise eight
concurrent computations, a reconstructed service/independent database pool,
and competing replacement writes. The result and timestamp remain stable.
See [audit checkpoint](../../../testing/production-readiness/audit-next-items-results.json).

This fixes local tally persistence. The reviewed encrypted tally, distributed
worker execution and independent verification remain TASK-011/TASK-019 gates;
concurrent replicas can still compute before the first result commits.
Production cryptography stays blocked.
