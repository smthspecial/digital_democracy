## Finding

Severity: **High**. Assessment: **SEC-04**.

The real TS approval controller and Postgres accepted valid T1 and T2 contexts for a seeded active auditor, despite the T3 requirement. A test validator supplied these contexts; real passkey authentication was not bypassed. Domain routes collect assurance but do not inspect it.

## Evidence

See [security report](../../../testing/security/REPORT.md) and its sanitized
memory/Postgres result files. Source locations, fixtures and scope limits are
recorded there. Run [TP-016](../../technical/test-plans/tp-016.md) for reproduction.

## Required correction

Add a simple minimum-assurance guard matching AUTH-010, preserving citizen, role, ownership and COI checks. Reject unknown tiers and return step-up-required responses.

## Verification

TS citizen writes enforce T2, with T3 on governance/IAM/revocation and residency/scope review. Unknown assurance values are denied. Existing public reads and own-identity T1 access follow the requirements.

See [remediation](../../../testing/security/REMEDIATION.md) and
[final verification](../../../testing/security/remediation-validation.json) for
regression results, positive controls and deployment limits.
