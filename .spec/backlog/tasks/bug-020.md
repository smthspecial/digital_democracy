## Finding

The local Go migration job inherits the image's production environment while
using a development plaintext database. Compose has no Prisma migration job,
and the TypeScript runtime lacks its required identity-hash secret. The README
still describes automatic Go migrations and a TypeScript routing shell.

## Fix and verification

- [x] Explicit development mode and separate migration images/jobs; no admin
  database URL in the API runtime environments.
- [x] Private stable local secrets, restricted per-app logins and configurable
  loopback ports; no dependency on production DNS, mesh or additional people.
- [x] One command builds, stops local writers, waits for final database startup,
  runs both migrations and starts the runtimes together after success.
- [x] Bound local runtime restart attempts for transient connection startup
  failures; migration jobs never automatically retry or launch APIs on failure.
- [x] Verify fresh startup, both runtime database connections, repeat startup
  without data/key loss and failure stopping before runtime launch.

All [35 live local checks](../../../testing/production-readiness/local-development-results.json)
pass, including separate restricted-role connections, cross-database denials,
HTTP access denials and complete restart with retained synthetic data/schema
history/keys. Two failure-sequencing tests prove either migration failure
prevents runtime launch. APIs and web remain running only on loopback.

Production crypto, network and review requirements are unchanged. Local
development uses synthetic data and has no cryptographic ballot verifier.
